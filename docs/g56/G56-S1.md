## Bölümler (ana sayfadaki sıra tasarımdaki gibi; pack hariç)
0. **Kampanya şeridi:** mevcut `banner_rows`/`banner_cells` sistemi aynı kalır. Görseller sonra Claude Design'dan gelecek; bu turda yalnız hedef bağlantıları: banner hücresi `Davet ekranı`, `paywall (Fresh yıllık seçili)`, `menü/liste (kategori)`, `kampanya detayı` hedeflerine gidebilmeli (mevcut link tipi şemasına ekle; yeni tip gerekirse migration). Koşulu sağlamayan banner sıradan çıkar (ör. Davet misafirde, "ilk siparişe özel" siparişi olanda gizli) — koşul hücre bazında opsiyonel alan.
1. **Kategori çipleri:** Tüm ürünler · Yüksek protein · 500 kcal altı · Vegan · Düşük karbonhidrat · Tatlı · İçecek. Dokununca **Filtrelenmiş liste** ekranı (`EkScr scr="liste"`). Filtre kuralları tek yapılandırma dosyasında (eşikler: yüksek protein ≥ 30 g, düşük karbonhidrat ≤ 20 g; vegan/tatlı/içecek mevcut kategori/etiket alanlarından — ürün şemasını incele, alan yoksa LOG + SORULAR, uydurma eşleme yok).
2. **Tekrar sipariş ver:** yalnız ≥ 1 tamamlanmış siparişi olanda; son 3 sipariş (görseller, ürün adları, tarih, toplam). Düğme → kalemler mevcut sepet mağazasına eklenir + bildirim (`st="toast"`, "Sepete git"). Satışta olmayan ürün varsa `st="oos"` uyarısı ve yalnız kalanlar eklenir. Seçenekli ürünlerde eski seçimler geçerliyse korunur, değilse ürün sayfası açılır.
3. **Kalan kalorine uygun öğünler (öne çıkan):** kalan = bugünkü hedef − loglanan (mevcut gün halkası verisi). Dolu: kalan ≥ ürün kcal olan ürünler, proteine göre sıralı, "Gününe uyar" etiketi. Hedef dolduysa (`st="done"`): ≤ 400 kcal hafif ürünler, "Hafif bir şey?". Profil/hedef yoksa `st="empty"` + "Hedefimi belirle" → mevcut profil oluşturma akışı (G47 kapısı). Bu bölüm tasarımdaki gibi bulanık renkli zemin + cam yüzey.
4. **Planından sipariş et:** yalnız kişisel planı olanda. Bugünün plan öğünleri ↔ eatkcal ürünü eşlemesi: plan öğününde ürün kimliği varsa o; yoksa aynı öğün tipinde kcal ±10 % en yakın ürün; eşleşme yoksa satır gizlenir (hepsi eşleşmezse bölüm gizli). "Hepsini sepete ekle". Eşleme kuralını LOG'a yaz.
5. **Bu hafta en çok sipariş edilenler:** migration: `top_products_week(p_limit int default 10)` RPC (son 7 gün, tamamlanmış/teslim edilmiş siparişler, aktif ürünler, sıra + adet); < 3 ürün → boş → bölüm gizli. Kartlarda sıra numarası; "Bu hafta [N] sipariş" etiketi gerçek adetle.
6. **Arkadaşını davet et:** banner biçiminde kart (giriş yapmış herkese; misafirde gizli) + **Davet ekranı** (`davet`, `davetBos`, `davetKopya`) + **Profil giriş satırı**. Sunucu (migration):
   - `referral_codes(user_id pk, code unique, created_at)`; `my_referral()` → kod yoksa üretir (6–8 karakter, karışmayan harf/rakam), kod + davet geçmişi döner.
   - `referrals(id, referrer_id, referee_id unique, code, status 'pending'|'earned'|'void', order_id, created_at, earned_at)`.
   - `apply_referral_code(p_code)`: yalnız hiç siparişi olmayan kullanıcı, kendi kodu değil, kişi başı bir kez.
   - İlk siparişi teslim edilince (mevcut sipariş durum akışına tetik/fonksiyon) iki tarafa mevcut kupon sistemiyle kupon; tutar ve minimum sepet `settings` tablosunda (`referral_reward_tl`, `referral_min_order_tl`, boşsa ödül verilmez). Kötüye kullanım: aynı cihaz/telefon kontrolü mevcut veriyle yapılabiliyorsa yap, yoksa LOG'a öneri.
   - Kod girişi: Davet ekranında değil, kayıt sonrası ya da sepette "Davet kodun var mı?" satırı (mevcut kupon alanının yanında, tasarım diliyle).
   - Paylaşım: sistem paylaşımı, metin TR/EN: kod + mağaza bağlantısı.
   - Yeni bayrak `davet` (migration'da `enabled=false`); kapalıyken hiçbir davet girişi/banner'ı görünmez.
   - **Rota adı `EkInvite`** (eatkcal v2 rotalarına kaydet). Banner hedefi `Invite` → `EkInvite` zaten bağlı (`bannerTargetToEk` kind `screen`). Kampanya 3 banner hücresi (`5b1e0c2a-…-2026110000c3`) kapalı duruyor; LOG'a "davet yayına girince hücreyi aç" notu yaz.
